# Asset Store 素材の導入手順

このプロジェクトは、見た目と演出に Asset Store の無料素材を使います。
**ライセンス上、素材そのものは GitHub に含められない**ため、クローンした人が各自でインポートし、**自分の手でゲームに組み込みます**。
素材が 1 つも無くても「カプセル人間＋プリミティブ」でゲームは動くので、急がなくても大丈夫です。

組み込みの考え方はどれも同じで、**決められた名前の Prefab を `Assets/Resources/` の決められたフォルダに置く**だけです。
シーンや既存の Prefab は編集しません（起動時に `ModelLoader` などが名前で探して差し替えます）。

| 置くもの | 置き場所（名前は大文字小文字まで厳守） | 使う素材 | 無いとき |
|---------|----------------------|---------|---------|
| プレイヤーの見た目 | `Assets/Resources/Characters/Player.prefab` | Character Controllers のロボット | 青いカプセル |
| 敵の見た目 | `Assets/Resources/Characters/Enemy.prefab` | 同上（色は EnemyData が付ける） | 白いカプセル（種類ごとの色） |
| 演出 8 種 | `Assets/Resources/Effects/<演出名>.prefab` | Particle Pack | 演出なし |
| アイテムの見た目 3 種 | `Assets/Resources/Items/Sword.prefab` / `Shield.prefab` / `Potion.prefab` | Household Items | 色付きのひし形 |
| ステージ装飾 | `Assets/Resources/Stage/Decorations.prefab` | SimplePoly City | 装飾なし |
| 効果音・BGM | `Assets/Resources/Sounds/<音名>.mp3` など | フリー素材サイトから各自でダウンロード（後半の章） | 無音 |

`Assets/Resources/` の中身はどれも素材を参照する（または素材そのもの）ので、`.gitignore` で Git から除外されています。
自分の PC にだけ存在し、クローンした人はそれぞれ自分で作ります。

**作業量の目安とおすすめの順番**：音（約 30 分、いちばん簡単で効果が大きい）→ 3-4 アイテム（約 30 分）→ 3-1 プレイヤー（約 90 分）
→ 3-2 敵（約 30 分）→ 3-3 演出（1 つ 10 分 × 8）→ 3-5 装飾（好きなだけ）。全部で半日前後。1 つ終わるごとに Play して確認すると迷いません。

## 使う素材（すべて無料・すべて URP 対応、SimplePoly City は変換が必要）

| 役割 | Asset Store での名前（リンク） | 提供元 | インポート先 | 必須？ |
|------|-------------------------------|--------|------------------------------|--------|
| キャラクター（プレイヤー・敵） | [**First Person + Third Person \| Character Controllers**](https://assetstore.unity.com/packages/essentials/starter-assets-thirdperson-updates-in-new-charactercontroller-package-196526) | Unity Technologies | `Assets/Starter Assets/` | 推奨（無いとカプセル） |
| 演出（爆発・火花） | [**Particle Pack**](https://assetstore.unity.com/packages/vfx/particles/particle-pack-starter-assets-127325) | Unity Technologies | `Assets/UnityTechnologies/ParticlePack/` | 任意（無いと演出なし） |
| アイテムの見た目（剣・盾・回復薬） | [**Low Poly Basic Items Pack - Household Items**](https://assetstore.unity.com/packages/3d/props/low-poly-basic-items-pack-household-items-249507) | Kabungus | `Assets/Kabungus/` | 任意（無いとひし形） |
| ステージ装飾（街並み・街灯・小物） | [**SimplePoly City - Low Poly Assets**](https://assetstore.unity.com/packages/3d/environments/simplepoly-city-low-poly-assets-58899) | VenCreations | `Assets/SimplePoly City - Low Poly Assets/` | 任意（無いと装飾なし） |

Character Controllers は Unity 公式の「Starter Assets」というサンプル集で、インポートすると `Assets/Starter Assets/` に入ります。
**この手順書では以後「Starter Assets」と呼びます。** 一人称／三人称のキャラクターコントローラーのサンプルですが、このサンプルで使うのは
**ロボットのモデルとモーションだけ**です（付属スクリプトは使いません）。
プレイヤーも敵もこの同じロボットで、色で見分けます（プレイヤー＝青、敵＝種類ごとの色、ボス＝大きい）。
SimplePoly City だけは Built-in 用のマテリアルなので、手順 3-5 で URP 用に変換します。

## 手順

### 1. Asset Store でマイアセットに追加する
1. ブラウザで Unity ID でサインインした状態で、上の表のリンクを開く。
   **Unity Hub にサインインしているのと同じ Unity ID** を使うこと（違うと Unity 側の一覧に出てきません）。
2. それぞれのページで **Add to My Assets**（無料）。4 つとも同じ手順。

### 2. Unity にインポートする
1. Unity でこのプロジェクトを開く（一度 `Main.unity` を Play して動くことを確認しておく）。
2. `Window > Package Management > Package Manager` を開き、**左の一覧から My Assets** を選ぶ（古い Unity では左上のドロップダウン）。
   一覧が空なら、Unity Hub 右上のアカウントが手順 1 と同じ Unity ID か確認し、更新ボタン（↻）を押す。
3. 素材を選び **Download** → **Import** → インポート画面で **Import**（全部チェックのままで OK）。
   - Starter Assets と Particle Pack は、Cinemachine / Input System / Post Processing などの
     パッケージが一緒に入ります。**そのままでも動きます**（片付けたい場合は下の「Starter Assets の不要物を片付ける」参照）。
   - **Starter Assets のインポート直後に「新しい Input System を有効にするために再起動しますか？」というダイアログが出たら「No」**。
     Yes を押すと `Active Input Handling` が変わり、**移動も Space も J も一切効かなくなります**。
     押してしまった場合は `Edit > Project Settings > Player` の **Active Input Handling** を **Input Manager (Old)** に戻し、Unity を再起動してください。
   - Starter Assets のインポート直後に **`Library/PackageCache/com.unity.splines/...` のコンパイルエラーが大量に出る**ことがあります
     （Cinemachine が必要とするパッケージの導入に失敗したとき）。**まず Unity を再起動**してください。
     直らなければ、下の「Starter Assets の不要物を片付ける」の手順で Starter Assets のスクリプトを消してから Cinemachine を Remove すると消えます。
   - Particle Pack は 150MB あるので少し時間がかかります。「I Made a Backup. Go Ahead!」というダイアログが出たら押して進めてください。
     これは Particle Pack に入っている古いスクリプトを Unity が自動更新する確認で、**自分のファイルや授業のスクリプトは変わりません**
     （最悪でも clone し直せば元に戻ります）。
4. インポート先のフォルダ名を変えないでください（`.gitignore` がこのフォルダ名で除外しています）。

### 3. 素材をゲームに組み込む（手作業）

ここからは Unity 上での手作業です。全部やらなくても、やった分だけ本物に変わります。

- README の「シーンは触らない」は、**Player や Door などの既存オブジェクトを編集しない**という意味です。
  作業用のオブジェクトを Hierarchy に一時的に置くのは問題ありません。Prefab 化したら削除するので、シーンは元どおりになります。
- 作業は `Assets/Scenes/Main.unity` を開いたまま行って構いません（カプセルと背丈を比べられるので便利）。
  閉じるときに「Save changes to Main.unity?」と聞かれたら、作業用オブジェクトを消していれば **Save でも Don't Save でも OK** です
  （消し忘れが不安なら Don't Save）。空のシーン（`File > New Scene`）で作業してもかまいません。
- 名前の注意：作る Prefab の名前 `Player` は、Git 管理の `Assets/Prefabs/Player.prefab` や Particle Pack の `Player.prefab` と同じ名前です。
  **保存先は必ず `Assets/Resources/Characters/`**。Project ビューで置き場所を確認してから Play してください。

#### 3-1. プレイヤーの見た目（`Resources/Characters/Player.prefab`）

使うファイルはすべて `Assets/Starter Assets/Runtime/ThirdPersonController/Character/` の下にあります。
いきなり全部作らず、**手順 1〜3 と 7〜8 だけ先にやって Play**（白いロボットが立っていれば成功）→ そのあと 4〜6 を足す、と進めると迷いません。

1. **フォルダを作る**：Project で `Assets/Resources` を右クリック → Create > Folder → `Characters`。
2. **モーションの読み込み設定**：`Animations/` の次の 4 つの fbx を 1 つずつ設定します。
   fbx をクリック → Inspector 上部の **Animation** タブ → 上のクリップ一覧でクリップを選ぶ → 下へスクロール、の順に探します。

   | fbx | 入っているクリップ | Loop Time | Events |
   |-----|------------------|-----------|--------|
   | `Stand--Idle.anim.fbx` | Idle | **オン** | あれば削除 |
   | `Locomotion--Walk_N.anim.fbx` | Walk_N（敵用） | **オン** | あれば削除 |
   | `Locomotion--Run_N.anim.fbx` | Run_N | **オン** | あれば削除 |
   | `Jump--Jump.anim.fbx` | JumpStart, JumpLand | オフのまま | あれば削除 |

   - **Loop Time**：チェックを入れる。Jump 系には入れない。
   - **Events**：同じ画面の下の方にある **Events** の折りたたみを開く。タイムラインに白い小さなマーカー（`OnFootstep` / `OnLand`）があれば、
     クリックして **Delete キー**（または右クリック → Delete Animation Event）。受け取るスクリプトがこのプロジェクトには無いので、
     残すと再生のたびに「receiver が無い」というエラーが Console に出ます。
   - **Root Transform Position (XZ)** の **Bake Into Pose** にチェックが入っていることを確認（通常は入っています。モデルが前に滑っていくときはここ）。
   - 最後に一番下の **Apply**。
3. **モデルを置く**：Hierarchy で右クリック → Create Empty → 名前を `PlayerModel`、Position (0,0,0)。
   `Models/Armature.fbx` を Project から `PlayerModel` の上にドラッグして子にし、Transform の ⋮ メニューから Reset（位置 0・回転 0・スケール 1）。
   Scene ビューで Player のカプセル（高さ約 1.8m）と背丈を比べ、ずれていれば Armature の Scale で合わせる。
   `Armature.fbx` の Rig タブで **Animation Type が Humanoid** になっていることを確認（違っていたら Humanoid にして Apply）。
4. **マテリアル**：fbx のロボットはマテリアル未設定（グレー）なので割り当てます。
   Hierarchy で `Armature` の左の ▶ を開き、**`Geometry` → `Armature_Mesh`** を選ぶ（`Armature` 自体には Animator しか付いていません）。
   Inspector の **Skinned Mesh Renderer > Materials** に 3 枠（Element 0〜2）があります。
   - まずは簡単な方法：`Assets/Resources/Characters/` で右クリック → Create > Material → `M_Player`、Shader は `Universal Render Pipeline/Lit` のまま、
     **Base Map** の色を青（例 `5A8CFF`）に。これを 3 枠全部にドラッグ。→ 単色の青いロボットになります。
   - テクスチャ付きにしたい人：`Materials/` の `M_Armature_Body` `M_Armature_Arms` `M_Armature_Legs` を **Ctrl+D** で複製 →
     `Assets/Resources/Characters/` に移動 → 名前を `M_Armature_Body_Player` のように直す（複製直後は `M_Armature_Body 1` という名前）→
     それぞれ Base Map の色を青に → 枠の順に **Element 0 = Body、1 = Arms、2 = Legs** でドラッグ。
5. **Animator Controller を作る**：`Assets/Resources/Characters/` で右クリック → Create > **Animation** > Animator Controller → `PlayerAnimator`。
   ダブルクリックで Animator ウィンドウを開き、
   - **Parameters** タブ（左上）で「+」→ `Speed`（Float）、`Jump`（Trigger）、`Attack`（Trigger）、`Damage`（Trigger）を追加。
     （Attack は今はモーションが無いが、スクリプトが SetTrigger するので名前だけ必要）
   - **ステートを作る**：Project で fbx の ▶ を開くとクリップが見えるので、クリップを Animator ウィンドウへ**直接ドラッグ**すると
     Motion 設定済みのステートができます（右クリック → Create State > Empty で作って Inspector の Motion に入れても同じ）。
     | ステート名（作ったら名前を直す） | クリップ | 入っている fbx |
     |---------|------------------|---------------|
     | `Idle` | Idle | `Stand--Idle.anim.fbx` |
     | `Run` | Run_N | `Locomotion--Run_N.anim.fbx`（`Run_N_Land` と間違えない） |
     | `Jump` | JumpStart | `Jump--Jump.anim.fbx` |
     | `Damage` | JumpLand | `Jump--Jump.anim.fbx`（着地でしゃがむ動きを被弾リアクションに流用） |
     `Idle` を右クリック → **Set as Layer Default State**（オレンジ色になる）。
   - **遷移を作る**：ステートを右クリック → Make Transition → 行き先をクリック。できた矢印をクリックすると Inspector に設定が出ます。
     Conditions は「+」で追加。Transition Duration と Can Transition To Self は **Settings** の折りたたみの中にあります。
     | 遷移 | Has Exit Time | Conditions | Transition Duration |
     |------|---------------|-----------|---------------------|
     | Idle → Run | オフ | `Speed` Greater 0.1 | 0.15 |
     | Run → Idle | オフ | `Speed` Less 0.1 | 0.15 |
     | Any State → Jump | オフ | `Jump` | 0.05（**Can Transition To Self** をオフ） |
     | Jump → Idle | オン（Exit Time 0.85） | なし | 0.15 |
     | Any State → Damage | オフ | `Damage` | 0.05（Can Transition To Self オフ） |
     | Damage → Idle | オン（Exit Time 0.85） | なし | 0.15 |
     （Idle ⇄ Run の 2 本は重なって選びにくいので、矢印の端の方をクリックする）
6. **Animator を設定**：Hierarchy の `Armature`（fbx のルート。Animator が付いている）を選び、
   **Controller** に `PlayerAnimator`、**Apply Root Motion** をオフ、**Culling Mode** を Always Animate。
7. **Prefab 化**：Hierarchy の `PlayerModel` を `Assets/Resources/Characters/` にドラッグ → 名前を **`Player`** に変更（`Player.prefab`）。
   Hierarchy の `PlayerModel` は削除。
8. Play → カプセルが青いロボットになり、移動で走り、Space でジャンプ、被弾でしゃがむ。

> なぜこの構造か：Player の Prefab（Git 管理）には `ModelRoot` という空の子があり、そこに付いた `ModelLoader` が起動時に
> `Resources.Load("Characters/Player")` で見つけた Prefab を子として生成し、カプセルを消します。
> だから **Player 本体の Prefab やシーンは一切触らずに**見た目だけ差し替わります。

#### 3-2. 敵の見た目（`Resources/Characters/Enemy.prefab`）

3-1 と同じ手順で、次だけ変えます。

- 作業用オブジェクト名 `EnemyModel`、Prefab 名 **`Enemy`**。
- マテリアルは複製せず、元の `M_Armature_Body` `M_Armature_Arms` `M_Armature_Legs` をそのまま Element 0〜2 に入れる
  （色は実行時に `EnemyBase` が `EnemyData.tintColor` で全身に付けるので、白っぽいままで OK）。
- Animator Controller は `EnemyAnimator`。Parameters は `Speed`（Float）と `Damage`（Trigger）だけ。
  ステートは `Idle`（Idle）、`Walk`（Walk_N）、`Damage`（JumpLand）。遷移は Idle ⇄ Walk（Speed 0.1）と Any State → Damage → Idle。
- Play → 3 種類の敵とボスがロボットになり、種類ごとの色とボスの大きさは自動で付く。

#### 3-3. 演出（`Resources/Effects/<演出名>.prefab`）

Particle Pack（`Assets/UnityTechnologies/ParticlePack/`）の Prefab を、ゲーム用に小さく・一回きりにして名前を付け直します。
ゲームが呼ぶ演出名と、元にする Prefab は次の 8 つ（元の Prefab は Project の検索欄に名前を入れると見つかります）。

| 演出名（Prefab 名を厳守） | いつ出るか | 元の Prefab | Scale | 放出時間（Duration）の上限 | 追加の設定 |
|------|------|------|------|------|------|
| `EnemyDie` | 敵撃破 | SmallExplosion | 0.8 | そのまま | |
| `BossDie` | ボス撃破 | BigExplosion | 1.0 | そのまま | |
| `EnemyHit` | 弾が敵に当たった | MetalImpacts | 0.6 | 0.25 秒 | |
| `PlayerHit` | プレイヤー被弾 | MetalImpacts | 0.8 | 0.3 秒 | |
| `Attack` | 弾が敵・壁に当たった場所の閃光 | MuzzleFlash | 0.8 | 0.2 秒 | |
| `Pickup` | アイテム取得 | EllenRespawn | 0.5 | そのまま | キャラクターの除去（手順 4） |
| `ChestOpen` | 宝箱（開き終わり） | FireFlies | 0.5 | 0.8 秒 | 各 Particle System の **Start Lifetime を 1.5**、**Emission の Bursts を「Time 0, Count 25」の 1 行だけ**に（元は 20 秒漂うホタル） |
| `Checkpoint` | セーブ | Respawn | 0.8 | そのまま | |

1 つずつ、次の手順で作ります。

1. `Assets/Resources` に `Effects` フォルダを作る。
2. 元の Prefab を Hierarchy にドラッグ → 右クリック → **Prefab > Unpack Completely**（元の Prefab と縁を切る）。
3. 名前を演出名（例 `EnemyDie`）に変え、Position (0,0,0)、Scale を表の値に。
4. **いらないものを外す**：
   - ルートや子に **Mesh Renderer / Mesh Filter / Collider** が付いていたら Remove Component（MetalImpacts と Respawn のルートにはデモ用の球が付いていて、残すと「演出の後に球が出る」）。
   - 名前に **Decal** が付く子（弾痕用。空中で出すと弾に見える）は削除。
   - **マテリアル名に Distortion** が付く子（画面の歪み。環境によって大きな板になる）は削除。マテリアル名は、子を選んで
     Particle System の一番下の **Renderer** モジュールを開き、**Material** 欄で確認する（Hierarchy の名前には出ない）。
   - スクリプト（C# コンポーネント）が付いていたら Remove Component。
   - **EllenRespawn（Pickup 用）だけ**：デモ用のキャラクターが入っていて、残すとアイテムを取るたびに人型が現れます。次の 3 つを順に。
     (a) ルート `Pickup` の **Animator** を Remove Component。
     (b) `Ellen_Body` の **Skinned Mesh Renderer** を Remove Component（`Ellen_Body` 自体はパーティクルの親なので**消さない**）。
     (c) `Ellen_Skeleton` を削除。
     終わったあとの Hierarchy は `Pickup` → `Ellen_Body` → `Rings` → `Embers` / `Smoke` の 5 つだけになります。
5. **一回きりにする**：先に Scene ビュー右下の **Particle Effect** パネルで **Stop** を押す（再生中は Duration が変更できません）。
   ルートと子のすべての **Particle System** を選択し（Ctrl+クリックで複数選択すると一括で変えられます）、Main モジュールで
   **Looping** をオフ、**Play On Awake** をオン、**Stop Action** を None、**Scaling Mode** を **Hierarchy**（元は Local のものが多く、
   そのままだと手順 3 の Scale が粒の大きさに効きません）。
   表に放出時間の上限がある演出は **Duration** をその値以下にする（火花が延々と出続けないように）。表の「追加の設定」があればそれも。
6. `Assets/Resources/Effects/` にドラッグして Prefab 化（名前が演出名になっていることを確認）。Hierarchy から削除。
7. Play → 該当の場面で演出が出る。演出は `EffectLibrary` が生成し、パーティクルの長さに合わせて自動で消します。

#### 3-4. アイテムの見た目（`Resources/Items/Sword.prefab` など）

Household Items（`Assets/Kabungus/`）の Prefab を、同じ大きさにそろえて中心を合わせます。

| Prefab 名（厳守） | 元の Prefab | 役割 |
|------|------|------|
| `Sword` | Hatchet（手斧） | 攻撃力アップ |
| `Shield` | Pan（フライパン） | 防御力アップ |
| `Potion` | Medkit（救急箱） | 回復薬 |

1. `Assets/Resources` に `Items` フォルダを作る。
2. Hierarchy で Create Empty → 名前 `SwordModel`、Position (0,0,0)。元の Prefab をその子にドラッグし、Unpack Completely。
3. 子の Scale を調整して、一番長い辺が **約 0.7m** になるようにする（Scene ビューで Item のひし形と比べる）。
   Scene ビュー上部の **Pivot** を **Center** に切り替えると移動ギズモがモデルの中心に出るので、それが親の原点（0,0,0）に来るように
   子の Position を動かす（`ItemPickup` が原点を軸にくるくる回すため）。Rotation Z を 30 度ほど傾けると回転が分かりやすい。
4. 子に Collider やスクリプトが付いていたら Remove Component（Household Items には通常付いていません。当たり判定は Item 側にあります）。
5. `SwordModel` を `Assets/Resources/Items/` にドラッグ → 名前を **`Sword`** に。Hierarchy から削除。`Shield` `Potion` も同様。
6. Play → ひし形が本物に変わる。

#### 3-5. ステージ装飾（`Resources/Stage/Decorations.prefab`）

SimplePoly City（`Assets/SimplePoly City - Low Poly Assets/`）で街並みを作ります。配置は自由です。
ステージは **x -15〜15、z -2〜72** の細長い部屋（エリア A → B → C が奥に向かって並ぶ）で、壁の高さは約 2m です。

1. **マテリアルを URP 用に変換する**（これをしないと全部ピンクに見える）：
   `Window > Rendering > Render Pipeline Converter` → 上のドロップダウンを **Built-in to URP** → **Material Upgrade だけ**にチェック
   （Rendering Settings など他の項目は外す）→ **Initialize Converters** → **Convert Assets**。
   一覧に SimplePoly 以外のマテリアル（他の素材のサンプル用）が混ざっていても、まとめて変換して問題ありません。
   変換されないものが残った場合は、そのマテリアルを選んで Shader を `Universal Render Pipeline/Lit` に変え、テクスチャを **Base Map** に入れ直す。
   ツヤが強く感じたら Smoothness を 0.2 くらいに下げる。やり直したいときは SimplePoly のフォルダを右クリック → **Reimport**。
2. `Assets/Resources` に `Stage` フォルダを作り、Hierarchy で Create Empty → 名前 `Decorations`、Position (0,0,0)。
3. `Decorations` の子として、SimplePoly の Prefab を置いていく。Prefab は `Prefab/Buildings`、`Prefab/Natures`、`Prefab/Props` などの
   サブフォルダにあります（`Building_Bakery`、`Natures_Big Tree`、`Props_Street Light` など）。
   - **壁の外側**（x が ±17 より外、または z が -4 より手前・74 より奥）に建物や木。
   - **壁の内側**に街灯・ベンチ・コーンなどの小物を置いてもよい。SimplePoly の Prefab には **当たり判定（Collider）が付いていない**ので、
     プレイヤーも敵もすり抜けます。見た目だけなので、Switch や Door、看板に重ねないことだけ注意。
   - 足元が床（y=0）に来るように高さを合わせる。
4. `Decorations` を `Assets/Resources/Stage/` にドラッグして Prefab 化（名前 **`Decorations`**）。Hierarchy から削除。
5. Play → シーンの `Decorations`（空オブジェクト）の位置に街並みが現れる。

#### 3-6. 効果音・BGM（`Resources/Sounds/`）

音は **各自で用意**して `Assets/Resources/Sounds/` に置きます。必要な音の一覧、ファイル名、置き方は次の章を参照してください。
このサンプルで使っている音のダウンロード先も次の章にあります。

### 4. 確認
Play して、組み込んだものが差し替わっているか確認します。差し替わらないときは次を見直してください。
- Prefab の**名前**（`Player` `Enemy` `EnemyDie` `Sword` `Decorations` など。大文字小文字まで）
- **置き場所**（`Assets/Resources/Characters/` など。`Assets/Prefabs/` に入れてしまっていないか）
- Hierarchy に作業用オブジェクトが残っていないか
- Console に赤いエラーが出ていないか（出ていたら内容を読む。多くは Starter Assets の付属スクリプトのもの → 下の「片付け」）

## 効果音・BGM の一覧と差し替え方

音は **ファイル名で呼ばれます**。Inspector に割り当てる作業はありません。
`SoundLibrary.Play("Jump")` と書かれていれば `Resources/Sounds/Jump` という AudioClip を探して鳴らし、無ければ黙ります。

### 置き方

1. 音ファイル（wav / ogg / mp3 のどれでも可）を用意し、下の表の **ファイル名どおり**（拡張子以外）にリネームする。大文字小文字もそろえる。
2. **`Assets/Resources/Sounds/`** に入れる。
3. Play して確認。音量は `GameConstants.SeVolume`（効果音）/ `GameConstants.BgmVolume`（BGM）で一括調整。

全部そろえる必要はありません。置いた名前だけ鳴り、無い名前は無音です。
音は自分で録っても、フリー素材サイトから探してもかまいません。サイトごとに利用規約（クレジット表記の要否・再配布の可否）が違うので、
使う前に必ず確認してください。探し方の例：[効果音ラボ](https://soundeffect-lab.info/)、[OtoLogic](https://otologic.jp/)、[魔王魂](https://maou.audio/)。

> `Assets/Resources/Sounds/` の音ファイルは `.gitignore` で Git から除外しています（フリー素材の多くが再配布禁止のため）。
> 置いた音は自分の PC だけにあり、クローンした人はそれぞれ自分で置きます。**この除外を外して push すると素材の再配布になるので、外さないでください。**

## 仕組み（なぜシーンに直接置かないのか）

- シーンや Prefab が素材を直接参照していると、素材の無い人がクローンしたときに **Missing 参照だらけ**になります。
- そこでシーンには仮の見た目（カプセル・ひし形・空の Decorations）だけを置き、`ModelLoader` が起動時に
  `Resources.Load` で本物を探して差し替えます。演出は `EffectLibrary.Play("EnemyDie", 位置)` が `Resources/Effects/` を、
  効果音は `SoundLibrary.Play("Jump")` が `Resources/Sounds/` を探し、無ければ何もしません。
- 本物側の Prefab は手順 3 で各自が `Assets/Resources/` に作ります。`Resources/` 以下は素材と同じく
  `.gitignore` で除外しているので、**うっかりコミットしても素材が混入しません**。

`Resources` フォルダを使うときの注意：
- `Resources/` 以下のファイルは、使っていなくても**全部ビルドに含まれます**。不要なファイルを置きっぱなしにしない。
- ファイル名の**大文字小文字**は厳密に。Windows のエディタでは通っても、ビルドでは読めなくなることがあります。

## Starter Assets の不要物を片付ける（任意・手作業）

Starter Assets はキャラクターコントローラーのサンプル集なので、このサンプルで使う `Character` フォルダ以外に、
サンプルシーンやスクリプト、Cinemachine / Input System などのパッケージが一緒に入ります。
**そのままでも動きます**が、Console がうるさいときや Splines のエラーが出たときは次の順に片付けます（順番が大事です）。

1. **Starter Assets のスクリプトを消す**（これをしないと、次でパッケージを外したときにコンパイルエラーになる）。
   Project で `Assets/Starter Assets/` の次を削除：`Editor`、`Sample`、`TutorialInfo`、`Runtime/Common`、`Runtime/FirstPersonController`、
   `Runtime/InputSystem`、`Runtime/Mobile`、`Runtime/Settings`、`Runtime/SpaceRobotKyle`、`Runtime/ThirdPersonController/Scripts`、
   `Runtime/ThirdPersonController/Prefabs`、`Runtime/Unity.StarterAssets.asmdef`。
   **残すもの**：`Runtime/ThirdPersonController/Character/`（モデル・モーション・マテリアル・足音）。`Assets/Resources/` 以下の自作 Prefab は触らない。
2. **パッケージを外す**：`Window > Package Management > Package Manager` → 左の **In Project** → `Cinemachine` を選んで **Remove**。
   同じく `Input System` も Remove。「Input System パッケージを削除したので再起動が必要」と出たら **Restart the Editor**。
   （Particle Pack が入れた Post Processing / Timeline / Visual Scripting なども同様に Remove できますが、残っていても害はありません）
3. **入力設定を確認**：`Edit > Project Settings > Player` → Other Settings → **Active Input Handling** が **Input Manager (Old)** になっていること。
   違っていたら直して Unity を再起動。

## ライセンスの注意
- Asset Store の 4 素材は、それぞれの Asset Store ページに書かれたライセンスに従います（使う人が自分で My Assets に追加する必要があり、
  ファイルを他人に渡すことはできません）。効果音ラボ・OpenTracks の音も再配布禁止です。
- そのため、素材も音もこのリポジトリには入っていません。**自分のリポジトリに push するときも、`.gitignore` の除外を外さないでください。**
- 詳細は README の「ライセンス」を参照。
